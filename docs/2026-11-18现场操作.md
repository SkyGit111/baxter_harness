# 2026-11-18 双臂 Harness 现场部署与联调

这份流程对应 11 月 17 日准备的双臂版本。离线通过表示代码和配置格式已检查，不能表示真实相机外参、右臂 TCP、双臂避碰或抓取已经验收。候选配置保持 `commissioned=false`、`primitives.calibrated=false`；现场检查不会自动把它们改成 true。

当前推荐把 Astra 高层留在这台已授权的 Windows 电脑，Baxter 控制主机运行 ROS、共享 D455 和一个双臂桥。天数板子保留本地模型服务；API 加原语任务不需要为了部署本次代码重新下载模型。`--arms both` 表示高层可以逐步选择左右臂，执行仍然串行，不表示两臂同时运动。

打包前先查看 `git status --short`。打包器只读取 Git 索引中的已审查源码 blob，不读取工作区里未暂存的内容；本轮新文件和修改须经检查后加入索引才会入包。不要使用 `git add -A` 混入用户未审查的交接文档修改。正式发布按本轮确认后的提交打包，工具本身不暂存、不提交。

## 5 补齐右 TCP 和当天几何核验

先保持桥只读，检查现场配置使用的是当前 D455 外参、桌面平面/边界，以及左右工具的实际几何。桌面高度历史值约为 base z=-0.18 m，不能直接用它代替当天平面核验。桌面倾斜时使用平面 `n·p+d=0`；工作区 XY 多边形来自测量，不根据相机画面猜 base 坐标。

右臂长夹指的 TCP 仍需要独立测量。现在有只读固定点 pivot 工具：让同一个明确的 TCP 接触同一固定参考点，手动改变末端朝向后每次读一组位姿。至少 4 个、建议 6 个明显不同且非单轴重复的姿态；每次都要确认接触点没有滑动。仅“同一朝向下上下移动”无法求出完整 XYZ 偏移。

```powershell
python -m cix_harness.tcp_calibration capture --samples .local/right-tcp-samples.json --arm right --robot-port 9102
```

每次人工调整完成后重新运行一次 capture；这条命令本身不动手臂。采完后：

```powershell
python -m cix_harness.tcp_calibration fit --samples .local/right-tcp-samples.json --output .local/right-tcp-fit.json
```

拟合失败先检查固定点是否滑动、姿态是否多样；不要通过修改阈值把错误数据变成通过。结果包含 `tcp_offset_tool_m`、残差和 `commissioned=false`。用另一个独立参考姿态检查拟合结果，再将确认后的偏移写入右臂候选配置。它不会自动证明右臂可以抓取，也不会自动放行机器人。

也可用生成器把拟合值导入一个新候选目录，再对照合并当天核验结果，避免覆盖已编辑的现场配置：

```powershell
python -m cix_harness.prepare_site --template .local/full-table-active-config-20261113.json --geometry .local/full-table-geometry-20261113.json --right-tcp-fit .local/right-tcp-fit.json --output-dir .local/site-20261118/after-right-tcp
```

还要核验两臂连杆半径/工具包络、当前 URDF 覆盖，以及夹持物体包络。初始组合候选的 `inter_arm_clearance=null` 允许只读取图，但完整任务预览会明确返回 `clearance_unavailable`；填入可核验的包络后才能预检路径。`verified=false` 不是可跳过的默认值。相机、桌面、工具或机器人模型变化后需更新对应现场资料。

控制主机已有 ROS 参数 `robot_description` 时，可生成覆盖实际全部连杆名字的包络候选。下面数字仅用于生成明确未核验的初稿，不能声称是已测量尺寸；按实际连杆、夹爪和手持物体修改为能包住其外形的尺寸：

```bash
python3 -m cix_harness.collision --from-ros --dual-config ../site/config/baxter-dual.local.json --output ../site/config/baxter-dual.capsules.local.json --candidate-link-radius 0.15 --candidate-tool-radius 0.08 --candidate-tool-length 0.20 --candidate-held-radius 0.08
```

如需在原语的实际路径上附加 MoveIt 全身碰撞检查，在各自的 `arms.left.planning`、`arms.right.planning` 中设置 `"collision_backend": "moveit"`。若本次任务依赖 MoveIt 中的桌面碰撞体，将场景中已核对位置、尺寸的物体 ID 填入 `"moveit_required_world_objects": ["现场桌面ID"]`。留空表示只使用 MoveIt 当前拥有的物体。预览或执行仍使用同一个 dual bridge 和 harness 入口。已部署的 ROS 主机需要提供 `/get_planning_scene` 及 `/check_state_validity`。

预检覆盖整条原语关节曲线，每个执行阶段再次用实测起点检查。每个检查点填入实测另一臂和头部关节。MoveIt 返回碰撞、缺少指定物体、场景变化或反馈失效时会阻止该段执行。轨迹由现有 IK 与原语执行器生成。碰撞查询为离散采样，工程上的桌面余量、持物与实装夹指包络、原有双臂检查均需保留。日志中 `primitive_plan.moveit_full_path` 和阶段回执 `moveit` 提供采样数、已加载物体及尺寸、碰撞矩阵摘要与服务耗时。与实物的一致性由当日测量记录核验。

该命令只读模型并写候选，不控制机器人，也不自动把 `verified` 改为 true。留存的 URDF 文件也可用 `--robot-description-xml 文件路径` 代替 `--from-ros` 离线生成。工具包络坐标属于各自 gripper 框架，不能复制左手长度直接声称右手已测量。

检查并保存包络候选后，Ctrl+C 停止原只读桥，加载新配置继续只读预览：

```bash
python3 -m cix_harness.dual_bridge --config ../site/config/baxter-dual.capsules.local.json --port 9102
```

重新运行第 4 节的在线 preflight 和投影视图，确保看到的是本次新配置。此后预览和放行均使用这个 `.capsules.local.json`，不要又切回 `inter_arm_clearance=null` 的原始候选。

还需给两臂各记录至少一个实际可用的让位位置。候选配置的 `observation_tcp_m` 为空，系统不会把估算的停车点当成已经验证的位置。保持只读，手动把对应手臂摆到能让开目标视野、位于配置工作区内且不低于 transit 高度的位置；先用实时图确认视线，然后在控制主机执行：

```bash
python3 -m cix_harness.record_view --config ../site/config/baxter-dual.capsules.local.json --arm left --robot-port 9102
python3 -m cix_harness.record_view --config ../site/config/baxter-dual.capsules.local.json --arm right --robot-port 9102
```

两条命令分别在摆好相应手臂后运行，不要求一次摆好两臂。工具只记录遥测，不移动机械臂；记录后重启只读桥加载新配置。到该位置的真实路径仍要通过完整 IK 和双臂间距检查。若初始手臂位于桌面候选多边形外，先在只读状态手动摆到工作区内，再开始任务预览；当前规划器不会自行穿越未配置区域。

## 6 验证已有账号，随后预览任务与首个动作

首先复用已有授权，不重新登录：

```powershell
python -m cix_harness.chatgpt_auth status --credentials .local/chatgpt-session.json
python -m cix_harness.preflight --online --check-account --credentials .local/chatgpt-session.json --robot-port 9102 --output .local/preflight-account.json
```

`--check-account` 允许正常 OAuth 刷新和模型目录查询，不发送现场图像做推理。只有授权确已失效且标准刷新失败时，才通过项目 `login` 命令由用户在浏览器重新授权。不要复制 Codex 登录文件或把 OAuth 令牌传到板端。

下面命令会把新的场景图与必要任务状态发给 Astra，但默认只预览，不发电机动作：

```powershell
python -m cix_harness.harness --arms both --route hybrid --planner-provider api --api-auth chatgpt --chatgpt-credentials .local/chatgpt-session.json --api-model gpt-6.2-astra --robot-port 9102 --task '把一个清楚可见且可达的青色方块放到桌面空位' --task-kind generic
```

预检报告中的 `ik_preflight=pending_task_preview` 表示读遥测尚未证明任务路径可达。以上任务预览生成语义计划，并对第一个原语做目标定位与完整 IK/轨迹预检，随后退出；它不假装执行抓取来推测后续状态。后续每个原语会在真实执行到该步骤时，基于新状态单独检查全部路径。若首步是 code/compute，该轮预览只检查计算工具，尚未检查机械臂路径。核对日志是否明确完成预检，不能仅凭模型说“可执行”就算通过。工作区是实际三维工具范围；桌面投影用于选择支撑位置，高物体顶面会有视差，不能一律按二维多边形裁掉。

## 7 现场放行后才执行，同步记录各环节耗时

确认实际几何、右 TCP、双臂间隔和路径后，配置中的左右 `commissioned`、`primitives.calibrated` 及 `inter_arm_clearance.verified` 才能各自记录为已核验。不要仅为通过预检批量改标记，或自动扩大工作区。停止原只读桥，从同一发布目录启动有界运动桥，并在旁监护：

```bash
python3 -m cix_harness.dual_bridge --config ../site/config/baxter-dual.capsules.local.json --port 9102 --arm-motion
```

Windows 重新运行完整任务，它会重新观察和规划，不重放上一次预览的令牌：

```powershell
python -m cix_harness.harness --arms both --route hybrid --planner-provider api --api-auth chatgpt --chatgpt-credentials .local/chatgpt-session.json --api-model gpt-6.2-astra --robot-port 9102 --task '把一个清楚可见且可达的青色方块放到桌面空位' --task-kind generic --execute
```

用 `--arms right` 或 `--arms left` 可以限定当天首先验收的机械臂。运动桥共享有界预算和租约；过期后先确认现场状态，再通过正常重启更新租约，不能靠重发旧动作续跑。结束时 Ctrl+C 停止运动桥，以同一 `.capsules.local.json` 去掉 `--arm-motion` 重启恢复只读，并确认 `healthz.armed=false`。

先验收单臂真实抓放，再验收换臂后的新观察与桌面中转。当前双臂调度不等于空中直接交接：直接手递手需要另行定义双方抓持与释放契约。本轮最合适的双臂任务是各自取放，或把物体先放到双方可达的桌面中转区，再由另一臂重新定位抓取。

每次运行保留 `events.jsonl`、`timing-summary.json`、图像和任务状态快照。这些记录留在 `runs/`，不进公开部署包。特别查看：API 总耗时、授权耗时、首完整 SSE 事件、首非空文本增量、原语定位/IK/各运动阶段、结果核验与失败恢复；嵌套计时不能直接相加当总时长，缺失首文本时间不能当成零。

通信超时或执行回执不明时先读当前机器人状态，不重发原计划、不马上换另一臂补做。若某物体无法定位或路径不可达，保留失败证据，先改现场几何、目标选择或姿态。结束后恢复只读，并记录实际源码 manifest、配置版本、模型、双臂情况和已证实的任务结果。
