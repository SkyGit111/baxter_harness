# 搬位后任务优先级与抓取提速

2026-11-20。近期比赛验收任务为“机器人自身右臂抓起粉色方块，叠在指定方块上”。用释放后退开得到的新图确认两个物体的相对位置，同时核对右夹爪已经释放。先把常用位置的一次完整任务做顺，再扩大任务范围。

| 优先级 | 任务 | 已经交付 | 下一项验收 |
| --- | --- | --- | --- |
| P0 现场 | 新摆位标定与工作区 | 相机标定手册、桌面候选配置生成、左右臂工作区投影、TCP 工具 | 用新的 optical → base 外参和实测桌角生成新配置，用独立点核对新桌面。记录左右臂新起姿。底座搬动本身不会改变手指相对末端的 TCP，工具无变化可先复核已有测量 |
| P0 现场 | 恢复两臂及右臂堆叠 | 两臂共用相机与串行执行桥。全任务 XYZ 采样检查抓、抬、搬运、放置和退开，保留被拒的点及其原因 | 在新布局按目标手、抓取点及放置点分别预检，挑出左右臂和重叠区代表点，然后验证实际堆叠 |
| P0 速度 | 去掉冗长转腕、横移和上下探 | 新配置启用连续轨迹、直接到预抓位、方块对称抓姿、接触段限速和离台后带载限速。只读预览按段给出名义运动秒数 | 同一配置对照 `primitive_plan.motion_schedule` 和 `primitive_result.completed_stages`，查最慢阶段、限速关节、实际跟随和到位等待 |
| P0 可靠性 | 减少中途停止，保留真实碰撞和掉物的反馈 | 起抓脱离支撑面有专门检查。单段 IK 或几何候选失败，在发指令前试其他预抓路线及朝向。控制器跟随、停滞、原厂避碰均记入审计 | 包括一次右臂闭爪、离台、搬运、释放、退开。若被拒，定位阶段、关节和碰撞对象 |
| P1 规划 | 新布局下仍然过不了的路径 | 已盘点真实 URDF，提供 MoveIt 的只读场景、起姿冲突和预抓路径查询。现用执行器仍为 KDL 和本项目轨迹 | 若直接转场及候选都失败，用同一起姿和预抓目标比较 MoveIt。只有输出轨迹经过本项目完整检查、控制器适配和真机验收，才接管该段 |
| P1 感知和诊断 | 腕图是否帮助判定抓住、遮挡和放置，动作为什么慢 | Astra 可接收 D455 与所选手的腕图。新增按历史帧和 checkpoint 回放。已有 API 首字、总耗时与调用链，新增运行耗时报告可关联机器人审计 | 收集新摆位中有目标的抓后或放后腕图，检查有没有改变原本会错的判断。未采到的动作中间帧在报告中保留缺失 |
| P2 通用抓取 | 对未知形状做分割和抓姿候选 | 已评估 SAM 3、GraspGen、FORCA 与 PyRoKi 的依赖、机器人和夹具差异 | 方块的已知抓取点如果正确而动作仍慢，优先修执行。更多异形物体引入后，以目标掩膜、深度质量、长夹指抓姿候选能否通过同一检查为接入条件 |
| 并行模型路线 | 板端 VLM、π0.5、本体适配及微调 | 有模型调用、坐标审计、VLA 与原语混合调度、任务记忆及恢复。已有真机模型输出和执行链记录 | 单独查坐标轴、动作尺度、夹爪语义和方向。按效果决定是否采真机数据、使用仿真数据、量化或改用 API。双臂同时搬运、空中交接另需协调轨迹 |

## 175 秒花在哪里

11 月 17 日左臂成功抓取的运行号是 `20261117-142401-fe685a7e`。任务实测 209.36 秒，四次 API 请求合计 30.36 秒。控制主机的原语执行 175.33 秒，其中 174.40 秒用于运动。单次完整 IK 预检用时 0.052 秒，另一臂路径检查 0.309 秒。各项计时有包含关系。

| 旧路线 | 现场时间 | 从记录或代码可以确认 |
| --- | ---: | --- |
| 原地调整工具朝向 77.59° | 84.22 s | 旧左臂仅允许 0.03 rad/s。原来对每个 IK 小段独立做五次插值，每段的时间至少是最大关节位移除以限速的 1.875 倍，另有 0.15 s 下限 |
| 横移 9.40 cm | 25.99 s | 当时在高位完成独立的水平转场 |
| 下探 24.86 cm | 31.81 s | 旧逻辑把初始手位高度带到目标正上方，增加了垂直接近距离 |
| 抬升 24.99 cm | 32.03 s | 闭爪后又回到进场高度，任务本身配置的抬升距离是 10 cm |

这里的距离取相邻阶段的实测末端位置。旧左臂记录没有逐条关节命令，无法从这次日志中追认具体某个关节的等待秒数。右臂另一次运行有更详细的审计。其前一段排程 18.86 秒、实耗 19.07 秒，后一段排程 30.30 秒、实耗 63.10 秒时轨迹时钟仅推进 15.59 秒，累计减速和延迟 47.50 秒。另一次右臂停在 `right_s1` 跟随误差约 −0.0503 rad。新布局需要分别判断原厂头部避让、反馈跟随和主动调度这三类现象。

## 从毕设保留了什么

毕设的驱动向 SDK 传入一组目标关节角。抓取先去目标上方约 10 cm 的准备位，再竖直下探。SDK 的 `set_joint_position_speed` 使用比例，本项目的 `joint_speed_rad_s` 使用 rad/s。将比例直接填进本项目会改变物理意义。[Baxter-claw](https://github.com/SkyGit111/Baxter-claw)

本次在当前手位已足够高时，让平移、降低至准备高度、调整方块抓取方向在同一段完成。起手低时先原位抬升。最后沿竖直方向接近，在近接触区使用单独速度，闭爪后先慢速离台，再进入带载抬升。腕部有偏移时按真实 TCP 的直线插值。若直接路线的 IK 或碰撞预检失败，调用者可看到试过哪些朝向和分段路线。

同一历史起点与方块目标上，用方块对称抓姿生成的首选转角为 16.73°。从准备位到接触点的垂直距离为 8.66 cm，其中最后 4 cm 慢速。闭爪后的目标抬升为 10 cm。这组数值是旧场景上的几何回放。用新场景只读预览给出的 `nominal_motion_seconds` 是合计运动排程，夹爪操作、实际反馈减速、到位等待、API 延迟应分别从实测报告读取。

使用上述真实抓取的抬升后画面，对 GPT‑6.2 Astra 做了两次配对请求。两次使用相同任务信息、同一 D455 帧和同一回执（已抬升约 0.250 m，仍夹持）。这是根据保存证据重新构造的检查，不是对旧 API 请求逐字重放。

| 输入 | Astra 的检查结果 | API 请求耗时 | 首文本增量 | 授权准备 | 客户端总耗时 |
| --- | --- | ---: | ---: | ---: | ---: |

## 到实验室后的顺序

1. 确认本体 ROS master 为现场报告的 `192.168.1.100`，读取新起姿和新图。按手册采集、独立验证新外参，然后更新桌面平面、边界、TCP 核验和让位姿态。旧的已放行 JSON 只留作历史回放。[标定手册](AprilTag标定操作与交接手册.md)
2. 用 `python -m cix_harness.table_survey` 将新外参和沿桌边依次测得的桌角生成 `site/new-table-geometry.json`。可加入不参与拟合的桌面点检验高度，用相机和机械臂分别测得的同一三维点检验横向偏差。然后从新几何生成单独的候选目录。下面的速度供预览，现场按该臂反馈选取。实际工具测量通过 `--left-tcp-fit` 和 `--right-tcp-fit` 传入。[测量输入格式及命令](操作可达区域离线扫描.md)

   ```bash
   python -m cix_harness.prepare_site --template config/baxter-primitives.example.json \
     --geometry site/new-table-geometry.json --output-dir site/new-layout \
     --grasp-symmetry square --transit-speed-rad-s 0.08 --contact-speed-rad-s 0.02
   ```

3. 用实际安装的长夹指、持物尺寸和双臂 URDF 核验避碰模型，在新图中核对两臂工作区投影。拿两臂起姿、新桌面格点和真实放置目标运行完整任务采样。有连续 IK 的候选方可进入预览。两只手分别到得了同一点，也要分别检查它们到目的地的路径。[完整操作区域扫描和 MoveIt 用法](操作可达区域离线扫描.md)
4. 预览粉块到指定底块的任务，在目标手的 `primitive_plan` 查看 `selected_yaw_rad`、`selected_approach_path`、逐段速度和名义时长。预览已经很慢时先看抓姿、关节行程和限速。预览很快而实际很慢时优先查跟随、避让、循环延迟和到位等待。
5. 现场实测后读取报告。第二条命令列出已有的图像与检查点，可用 `--frame N --checkpoint K --output <新JSON>` 代替 `--list` 选取同一时刻的输入。

   ```bash
   python -m cix_harness.motion_report runs/RUN --audit site/robot-audit.jsonl
   python scripts/compare_planner_views.py --run runs/RUN --list
   ```

## 框架与插件的取舍

- **MoveIt 1** 适合在现有 ROS 1 环境里回答具体问题，例如“从这组肘姿，绕过头部是否还有到预抓点的路径”。现有 URDF 有 37 个带碰撞几何的连杆，覆盖头、躯干和标称指节。建场景时重点核对实际长夹指、夹持物、新桌面及 SRDF 允许碰撞对。**PyRoKi** 可在独立 Python/JAX 环境中优化已有轨迹，仍需提供一致的机构模型、场景和初值。[MoveIt 规划场景](https://moveit.github.io/moveit_tutorials/doc/planning_scene/planning_scene_tutorial.html) · [PyRoKi](https://github.com/chungmin99/pyroki)
- **NVIDIA/skills** 提供开发助手可用的工作流程，可借鉴 Isaac Sim 的 URDF 导入和碰撞体核查。**robotics-agent-skills** 中 ROS 1 调试及基于物体最终位置的任务判定与本项目直接相关。**Robium** 提供开发技能、CLI 和参考仿真应用，可用来复现策略或双臂仿真任务。三者的示例与本项目的 ROS 1 Baxter、长夹指和现场标定都需分别适配。[NVIDIA/skills](https://github.com/NVIDIA/skills) · [robotics-agent-skills](https://github.com/arpitg1304/robotics-agent-skills) · [Robium](https://github.com/robium-ai/robium)
- **FORCA** 展示了 SAM 3 分割、GraspGen 提候选、VLM 选抓姿、PyRoKi 做规划的组合，用的是 UR5e 和腕部力/力矩传感器。若方块颜色定位正确但关节运动慢，重型分割不会缩短当前运动段。扩大物体种类后再对照长夹指的几何、算力环境及抓姿成功证据评估。[FORCA](https://tanoom.github.io/forca/) · [GraspGen](https://github.com/NVlabs/GraspGen) · [SAM 3](https://github.com/facebookresearch/sam3)
