# 2026-11-17 规划、感知和执行优化

本次完成软件改动与离线回归，不恢复真机运动。实验室控制主机 `.102` 与天数板子 `.103` SSH 均超时，因此没有部署本次版本，也没有实测新的操作范围、执行速度或堆叠成功率。

## 已实现

1. **完整操作区域扫描**：`python -m cix_harness.reachability` 从保存的 URDF、左右臂姿态与标定配置读取数据，按 XYZ 网格及多个抓取朝向，检查 `pick → place/stack` 的完整路径。分别保存物体顶面 z、实际 TCP 路径 z、成功候选及失败步骤。保留区域内的孔洞，不把采样点的包围盒宣传为连续可达空间。运行方法见[操作可达区域离线扫描](操作可达区域离线扫描.md)。结果依赖初始姿态、放置目标、物体尺寸和标定；目前仍缺少实际扫描结果及完整躯干/同臂 mesh 碰撞认证。
2. **抓取朝向候选**：原语规划可配置绕 base Z 的多个抓取角度，优先较小的腕部旋转，并对每个候选执行完整 IK 与碰撞预检。失败的候选在运动前换方案，不把不连续的其他关节解直接发给机器人。持物放置保持当前工具朝向。
3. **头部检查**：可从实际 URDF 加入两个固定头部避让球；主路径检查及执行中检查共用几何。原厂避让/碰撞遥测在运动前及运动中检查，缺失或过期时不能发出运动指令。模型通过不代表原厂控制器必然不介入，实际触发时保留其对象名和状态。
4. **连续轨迹和分阶段速度**：可选择单调三次关节插值，内部 IK 点不再逐点停车。速度和加速度有解析上界；预检覆盖原始相邻 IK 点的整个关节区间盒，并对实际插值曲线做 FK、TCP 和桌面检查。每个执行段根据实时起点重新检查。细密的碰撞/IK采样继续保留，采样密度与实际移动速度解耦。
5. **Astra 双图输入**：默认输入 D455 和当前所选臂的新鲜腕部 RGB 图；日志记录实际发送的来源、尺寸、年龄、缺失原因及 API 延迟。腕部图过期、缺失或属于另一臂时回退总览图。目标 UV 始终对应 D455，腕图不直接替代深度坐标。
6. **完整调用链和细分耗时**：`events.jsonl` 有单调顺序号和 trace ID；`call-chain.json` 串联任务、子任务、执行后端、RPC、plan ID 和阶段。机器端每段包含开始/完成/失败、每秒进度、主要受限关节、速度、计划时间、反馈等待、控制循环延迟、到位等待及各项检查耗时。RPC、服务端和阶段时间互相嵌套，不能重复相加。

## 已有实测证据

左臂成功抓取那次机器人执行共 **175.333 秒**，其中运动 **174.401 秒**；整个任务约 209 秒，API 共 **30.359 秒**。

| 阶段 | 时间（秒） | 实际动作 |
|---|---:|---|
| 起始保持 | 0.359 | 起点确认 |
| 调整朝向 | 84.219 | 原地旋转约 77.59° |
| 横移 | 25.994 | 约 9.40 cm |
| 开爪 | 0.282 | — |
| 下探 | 31.812 | 约 24.95 cm |
| 闭爪 | 0.633 | — |
| 抬升 | 32.026 | 约 25.02 cm |

主要成本来自全程较低的关节速度 `.03 rad/s`、起始朝向调整，以及每个小 IK 段重新加减速。提高采样步长会降低检查分辨率，不能代替正确的连续时间参数化。新轨迹在同速 `.03 rad/s`、合成 `0.3 rad` 路径上的离线时间约 11.8–12.1 秒；旧调度随 20/100/300 个点为 18.75/18.75/45 秒。这些是调度计算，尚未测量实机提速。

固定保存观测上的一次 Astra 对比：D455-only 和 D455+wrist 均返回 `act`，目标 `uv=[0.577,0.645]`；API 分别约 **12.689/13.721 秒**，输入 token 为 **1621/1988**。这张腕图没有看到粉色目标，因此没有证明定位改善。后续应在接近、夹爪遮挡、闭爪及放置阶段采集有效腕图，再做同观测对照；不需要为比赛额外铺开学术消融。

## 配置和上线

每臂顶层配置可加入：

```json
{
  "planning": {
    "grasp_yaw_offsets_rad": [0, 1.5707963267948966, -1.5707963267948966, 3.141592653589793],
    "trajectory_mode": "continuous"
  },
  "joint_speed_rad_s": 0.03,
  "joint_acceleration_rad_s2": 0.12,
  "joint_speed_by_phase_rad_s": {"transit": 0.03, "contact": 0.02, "orientation": 0.03, "retreat": 0.03}
}
```

双臂 `inter_arm_clearance` 增加 `"check_head": true`、`"head_minimum_distance_m": 0.04`。这是工程几何检查参数，不是已经测得的原厂避让激活距离。先在原速度下验证新轨迹，再依据跟随和耗时记录提高非接触阶段速度；接触阶段单独限速。旧配置默认保持旧轨迹；新模式必须显式启用后进行完整预检。

## 外部工具接入顺序

- [FORCA](https://tanoom.github.io/forca/) 展示 SAM 3 → GraspGen → VLM 选抓姿 → PyRoKi，平台为 UR5e 与腕部力/力矩传感器。项目页尚未提供代码入口，不能称为已复用其完整运行时。
- [PyRoKi](https://github.com/chungmin99/pyroki)：Python 3.10+，可用 JAX CPU；适合独立规划服务，与 Noetic Python 3.8 隔离。局部优化与胶囊近似仍不能保证找到全局路径。
- [MoveIt](https://moveit.ai/install/)：现有 Noetic 主机适合评估 MoveIt 1 的完整机器人碰撞模型和路径规划，但已 EOL；长期维护考虑独立 MoveIt 2 服务。优先解决同臂/躯干碰撞和全局换姿态能力。
- [GraspGen](https://github.com/NVlabs/GraspGen) 与 [SAM 3](https://github.com/facebookresearch/sam3)：先作为外部感知/抓姿服务评估。官方 CUDA 环境和支持的夹爪模型不能直接等同 TY1100 COREX 与 Baxter 长夹指适配。
- [cuRobo](https://nvlabs.github.io/curobo/v0.7.6/get_started/1_install_instructions.html) 要求 NVIDIA/CUDA，不作为当前天数板子的即插即用依赖。

以上外部框架本次未安装或集成；本次接入的是当前 KDL 规划链的候选、几何、曲线和记录改进。

## 中断与恢复边界

已知的桌面起抓逻辑错误已有针对性回归；抓取后第一段竖直离开支撑面，不能要求起点已经满足悬空物体底部余量。未知电机执行结果、真实碰撞/避让、物体掉落和陈旧遥测仍需停下核验，不能靠忽略错误继续。候选 IK、朝向和头部路径不合格应尽量在运动前发现并换方案。

重新布置机器人或相机后，旧外参、桌面模型、工作区报告及保存姿态都必须重新核验；先比较任务的可操作范围，再决定后退、横移或调整桌面任务区。全桌候选边界不等于任意一臂可操作整张桌面。
