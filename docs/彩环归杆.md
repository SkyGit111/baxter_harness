# 桌面散环归杆

双臂桥的 `primitives.ring_peg` 配置启用这项任务。正常入口仍是 `python -m cix_harness.harness`。使用现场对应的 arm、bridge、Astra 和 `--route hybrid` 参数。一次处理一枚散环，杆上已有的彩环标记目标颜色。

每次 `observe` 都用当帧 D455 彩色、对齐深度和活动臂位姿生成 `ring_scene`。规划器在图中指定要夹的散环和要放的同色杆。夹持时由 `pick` 测量环边高度和开口宽度，可以从外缘两侧夹持，也可以在孔足够宽时夹一侧环壁。桌面误差较大时，下探深度会缩短，抬起后用持物遥测和新图核验。

`place` 从新图测在手环的孔心相对 TCP 的偏移，运到对应杆尖上方。系统停止平移、取得下一帧并比较环孔与杆尖。配置近景腕相机时，它依据两者各自的高度和法向修正视差。若偏差仍可纠正，就生成一次有限幅的水平移动，并把该移动、张爪和撤离一起重新通过 IK、对臂与现场配置的碰撞预检。默认最多校正三次。两相机对位明显冲突时，运行记录会给出差异。

现场已手动验证配套的玩具可以启用 `matching_parts_verified`。当孔径与杆径的测量区间重叠，系统仍可在颜色、在手身份、指尖与环底高度、堆面落差以及当前中心偏差满足要求时进行重力释放。机器人在杆尖上方张爪。检查真实放置结果需要下一帧显示环堆层数增加，或可分辨的堆面抬升。若同一枚环落回桌面并重新定位成功，harness 会记录 `ring_missed_peg`，按步骤恢复策略重做抓取与放置。

| 现场要提供的配置 | 单位和用途 |
| --- | --- |
| `perception`、可选 `source_ring_id`、`destination_peg_id` | 当次颜色、桌板及杆的检测配置，可限定当前要处理的颜色 |
| `ring_thickness_m`、`grasp_inset_m` | 环厚写在 `ring_peg`，名义夹持下探深度使用原语配置中的 `grasp_inset_m` |
| `jaw_axis_tool`、`jaw_open_half_span_m`、`finger_half_width_m`、`fingertip_below_tcp_m` | 实际工具开合方向、打开时单指中心到 TCP 的横距、指尖包络和相对 TCP 的最低点 |
| `horizontal_uncertainty_m`、`vertical_uncertainty_m`、可选 `relative_xy_uncertainty_m` | 抓取位置、桌面高度、同帧杆尖对孔心定位的误差，当前轮廓残差另按帧计算 |
| `release_gap_m`、`max_drop_m` | 相对杆尖的初始悬空高度和到已挂环堆面的最大允许高度差 |
| `servo_step_m`、`servo_iterations` | 单次纠正上限（默认 8 mm）和每次放置的纠正次数（默认 3） |
| 可选 `wrist_alignment` | 活动图像尺寸、裁切后的内参 `K`、畸变 `D`、实测 `eef_T_optical`、环与杆尖的颜色范围及近景配准误差。实际两幅图都需要有能区分的目标特征 |

原语计划的 `ring_geometry` 留有抓取方式、参考点、允许的深度和目标偏差。机器人审计中 `ring_wrist_alignment`、`ring_servo_replanned`、`ring_release_checked` 分别记录近景测量和帧号、每一次水平修正、实际张爪依据。用 `python -m unittest tests.test_ring_peg tests.test_ring_wrist tests.test_ring_perception` 回放模拟夹持、视觉纠偏、落环验证及缺失观测。
